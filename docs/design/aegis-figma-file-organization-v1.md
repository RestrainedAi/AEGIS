# AEGIS Figma File Organization v1

Target file:
- `AEGIS Design Board v1`

Purpose:
- keep active product surfaces easy to find
- separate planning from actual screens
- make manual asset handling explicit
- reduce drift between daily product work and design work

## Page Structure

`00 Overview`
- file map
- usage notes
- working rules

`01 Board and IA`
- page maps
- screen inventory
- user flows
- Jira-to-screen planning

`02 sundrop.music`
- Harvest-facing product screens
- index pages
- controls pages
- future source, run, issue, and detail pages

`03 sundrop.cloud`
- Vault-to-YouTube product screens
- index pages
- controls pages
- future queue, publish, diagnostics, and operator pages

`04 Shared Patterns`
- reusable shells
- status tiles
- issue treatments
- queue states
- common cards and navigation patterns

`05 Asset Intake (Manual)`
- screenshots brought in by hand
- logos
- reference exports
- temporary imagery

`99 Archive`
- retired experiments
- replaced layouts
- dead-end concepts worth preserving briefly

## Working Rules

- Build real screens on the product pages, not in scratch space.
- Use `01 Board and IA` for planning work before a surface becomes real.
- Use `04 Shared Patterns` for reusable layout or state ideas.
- Use `05 Asset Intake (Manual)` as staging only, not permanent storage.
- Move stale concepts to `99 Archive` instead of leaving them mixed with active work.

## Asset Handling Note

Because asset push/pull support is still limited, assume:
- assets are imported manually
- layout and structure are what Codex can set up reliably
- durable asset placement should happen after manual intake on `05 Asset Intake (Manual)`
