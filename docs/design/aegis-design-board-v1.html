Object model
Source -> Run -> Item -> Issue -> Artifact

Behavior Rules

Trust and hierarchy

  1. Ops pages are dense and scan-first.
  2. Catalog pages are editorial and media-forward.
  3. Every detail page exposes lineage links.
  4. Unsafe actions are gated until backend authority exists.

Page Blueprints

Each card below is formatted like a board frame brief: goal, user, modules, states, and linked destinations.

1. Dashboard

Daily control tower

Goal
Show platform health, freshness, new content, and risk concentration.
Primary user
Content operations manager and technical operator.
Modules
Health summary, recent runs, stale sources, failed runs, new items, missing media, transcript coverage.
States
Healthy day, warning-heavy day, incident day, empty system.
Links to Runs List, Run Detail, Sources List, Source Detail, Catalog Browser, Issues View.
2. Sources List

Monitored input inventory

Goal
Scan what sources exist, which are healthy, and which need attention.
Primary user
Content operations manager and admin.
Modules
Search, platform and freshness filters, dense table, gated Add Source action.
States
No sources, filtered empty, mixed-health dataset.
Links to Source Detail, Runs filtered by source, Catalog filtered by source, Issues by source.
3. Source Detail

One source, one operating story

Goal
Explain source health, recent execution behavior, output volume, and known degradation.
Primary user
Content operations manager and admin.
Modules
Source header, health cards, latest run, run history, recent items, schedule or config, issues.
States
Healthy, stale, failed recent run, disabled.
Links to Run Detail, Runs List, Catalog Browser, Item Detail, Issues View.
4. Runs List

Execution history and live monitoring

Goal
Show what ran, what failed, and what is still active.
Primary user
Content operations manager and technical operator.
Modules
Date filter, status and pipeline filters, saved views, dense sortable table.
States
Real-time running, failed-heavy dataset, no runs for period.
Links to Run Detail, Source Detail, Issues View, Dashboard.
5. Run Detail

Stage-level explanation and evidence

Goal
Explain one run from start to finish with diagnosis-ready evidence.
Primary user
Technical operator and content operations manager.
Modules
Run header, metrics strip, stage timeline, processed items, errors, artifacts, logs.
States
Running live, partial completion, hard failure, successful completion.
Links to Item Detail, Source Detail, Runs List, Issues View, Dashboard.
6. Catalog Browser

Browse, filter, play, trust the data

Goal
Help reviewers find, evaluate, and play content quickly.
Primary user
Creative reviewer or curator, plus content operations manager.
Modules
Search, filter rail, active chips, sort, grid or table toggle, results area, mini-player, freshness stamp.
States
Loading, empty results, missing artwork, missing media, stale export warning.
Links to Item Detail, Source Detail, Run Detail via lineage, Issues via exception filters.
7. Item Detail

Asset completeness and lineage view

Goal
Confirm that an item is usable, complete, and traceable.
Primary user
Creative reviewer, admin, technical operator.
Modules
Header, artwork or player, metadata strip, transcript, artifacts, source and run lineage, raw metadata.
States
Fully complete, missing transcript, missing media, removed from source, processing.
Links to Catalog Browser, Source Detail, Run Detail, Issues View.
8. Issues View

Prioritized operational inbox

Goal
Tell operators what to fix first without pretending a ticketing system exists.
Primary user
Content operations manager and technical operator.
Modules
Severity summary, issue filters, grouping options, prioritized list, recommended action column.
States
No active issues, incident-heavy state, low-severity backlog.
Links to Run Detail, Source Detail, Item Detail, Runs List, Sources List, Dashboard.

Cross-Page Flows

These flows turn the screen set into a usable operating rhythm rather than disconnected pages.

Flow 1

Daily operations triage

Start from the Dashboard, identify risk, drill into runs or sources, inspect impacted items, then return to the overview to confirm residual risk.

Dashboard -> Runs List / Sources List -> Run Detail / Source Detail -> Item Detail -> Dashboard / Issues View
Flow 2

Stale source remediation

Move from a stale signal into source health, then into the run that explains the degradation and the downstream catalog impact.

Dashboard / Issues View -> Source Detail -> Run Detail -> Catalog Browser / Item Detail
Flow 3

Run failure diagnosis

Use the run detail page as the strongest diagnostic surface, with stages, evidence, affected items, and lineage back to the source.

Runs List -> Run Detail -> Item Detail -> Source Detail
Flow 4

Catalog review and validation

Browse from the catalog, inspect one item in depth, then follow lineage when completeness or provenance is in question.

Catalog Browser -> Item Detail -> Source Detail / Run Detail
Flow 5

Issue-led exception handling

Group exceptions by severity or source, open the affected object, then return to the queue to continue triage.

Issues View -> Run Detail / Source Detail / Item Detail -> Issues View
Flow 6

Future publish readiness

The publish path should remain explicitly gated until queue, API, and uploader contracts are production-safe.

Catalog Browser / Item Detail -> readiness checks -> queue and upload states later

Component Families

The board should support a reusable component language across operations, catalog review, lineage, and system feedback.

Shell and navigation

Structure the product clearly

  • Primary nav rail or top navigation
  • Global utility bar
  • Breadcrumbs and lineage breadcrumbs
  • Detail page tab sets
Status and freshness

Make system truth legible

  • Status badges for source, run, item, export, and upload
  • Severity badges and issue labels
  • Freshness indicators and stale notices
  • Incident, warning, and info banners
Data browsing

Support dense scan and quick narrowing

  • Search inputs and active filter chips
  • Filter rails or drawers
  • Saved view controls
  • Sort controls and density toggles
Data display

Balance operations and media review

  • Dense tables and metric cards
  • Media cards and thumbnail-plus-metadata rows
  • Queue-style review lists
  • Sectioned panels
Lineage and evidence

Trace why something happened

  • Source-run-item linkage modules
  • Stage timeline or progress tracker
  • Artifact lists and logs panels
  • Raw metadata blocks
Media review and action

Keep content usable without overclaiming control

  • Player module and artwork treatment
  • Transcript panels and completeness summaries
  • Conservative CTA patterns
  • Loading, empty, degraded, and gated states
